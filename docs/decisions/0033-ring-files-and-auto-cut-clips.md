# 0033. Ring files and auto-cut clips: rendered by tools, pack format 1 unchanged

- Status: accepted (defaults; the owner may override them in #173)
- Date: 2026-10-24
- Issue: #51

## Context

Pack format 1 already describes ringtones: variants with `when` conditions, `weight`, `loop` (whole file, play once,
or `startMs`/`endMs`), `fadeInMs`, and the 5 s to 6 min duration range. The brief also asks the packer and the pack
creator to "cut a 2 to 3 s notification clip from a song automatically".

The M9 spike ([report](../m9-report.md) §6, [ADR 0023](0023-call-ringtones-native-first.md)) found that Telecom loops
the **whole** ringtone file with `MediaPlayer` and has no loop points or fade-in. Loop points therefore cannot be
honored at ring time. They have to be rendered into the file Cucuto exports to `Ringtones/cucuto/`.

## Decision

1. **No new `formatVersion`.** Everything in #51 can be expressed in format 1. Ring files are derived data and never
   live in a pack. An auto-cut clip is an ordinary clip file. Every pack stays readable by every format 1 reader,
   including the app already in use. Tools may note a clip's origin in an `x-cut` key, which readers ignore.
2. **Ring file rule** ([pack format](../pack-format.md#ring-files)):
   - The intro once, then the loop section repeated the fewest whole times that reach **90 s**. The outro after
     `endMs` is left out.
   - `loop: false` is padded with silence to 90 s.
   - The fade-in happens once.
   - When nothing needs rendering, the file passes through unchanged.
   - Splices are sample-exact.

   90 s exceeds the usual 20 to 60 s before voicemail, so the wrap from the end back to the intro is rarely heard. The
   rule is `RingFiles` in `shared/pack-spec` `commonMain`, so the app (#52), packer and the browser build use the same
   rule. Golden plans live in `spec/fixtures/ring-files.json`, written by `spec/fixtures/generate.main.kts`.
3. **Ring files are Ogg Opus, 48 kHz, 64 kb/s per channel.** Android decodes Opus since 5.0 and reads it from Ogg
   ([Supported media formats](https://developer.android.com/media/platform/supported-formats)). Telecom opens ringtones
   with `RingtoneManager` → `MediaPlayer` in `system_server` (M9 report §3.3), and the stock Pixel ringtones are Ogg too.
   A 92 s mono file is about 0.8 MB.
4. **Hook finder** (`ClipCuts` in `commonMain`):
   - Take 50 ms RMS frames.
   - Find the loudest frame-aligned window of the clip length (default **2.5 s**, the middle of the brief's 2 to 3 s).
     The earliest window wins a tie.
   - Move the start back to the strongest onset within 250 ms.
   - Fade in over 10 ms and out over 200 ms.

   It is a heuristic and is not checked by validators. Sharing it means the same song gives the same clip in packer,
   the creators and the app.
5. **Packer** gets two commands and one `pack.yaml` entry:
   - `packer ring` renders ring files.
   - `packer cut` cuts a clip.
   - `- cut: song.flac` entries in `pack.yaml` cut clips at build time. These need ffmpeg and ffprobe, and so does
     `--opus`.

   The demo packs commit their cut clip, generated by `packs/generate.main.kts` through `packer cut`. Building them
   stays ffmpeg-free and byte-reproducible.
6. **Demo content**: Kitchen orchestra 1.1.0 gives the kettle "Kettle reel":
   - a 4 s intro, an 8 s loop and a 2 s outro, with `loop: { startMs: 4000, endMs: 12000 }` and `fadeInMs: 500`;
   - the clip "Kettle reel (hook)" cut from its loop.

   All of it is synthesized, CC0.

## Consequences

- #52 renders ring files on the phone from the same `RingFilePlan`: decode with `MediaCodec`, splice
  `plan.pieces(rate)`, encode Opus into Ogg with `MediaMuxer` (API 29+). It can copy pass-through files as they are.
- Loop settings change what users hear on calls. Telecom's own wrap at the end of a ring file (after at least 90 s)
  goes back to the intro and is not seamless; calls rarely ring that long.
- No error codes were added. Two fixtures cover existing loop rules more tightly: an open loop starting less than 1 s
  before the end, and a loop shorter than 1 s. One valid fixture covers a song-only character.
- The packer CI job installs ffmpeg so the ring and cut tests run there. Building the demo packs still needs none.
- The app imports these packs unchanged (`:core:pack` already stores ringtones with their loop settings). Nothing uses
  them until #52 and #53.
